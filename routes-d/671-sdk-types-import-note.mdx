# SDK Types Import Note

Almost everything you need comes from the package root, `@stellar/stellar-sdk`. Classes such as `Keypair`, `Asset`, `TransactionBuilder` and `Networks` are exported directly. The Horizon and Soroban RPC clients, and their types, are grouped under the `Horizon` and `rpc` namespaces.

```typescript
import { Keypair, Networks, Horizon, rpc } from '@stellar/stellar-sdk';
import type { Asset } from '@stellar/stellar-sdk';

// Horizon record and response types
type Balance = Horizon.HorizonApi.BalanceLine;
type AccountRecord = Horizon.ServerApi.AccountRecord;

// Soroban RPC client and types
const rpcServer = new rpc.Server('https://soroban-testnet.stellar.org');
```

Use `import type` for anything you only need as a type. It is erased at build time, so it adds nothing to your bundle.

## Tree shaking

- Importing from the package root is the simplest option, and recent SDK releases are better at tree shaking, but a bundler can only drop code it can prove is unused. Namespaces such as `Horizon` and `rpc` are used as a whole, so importing them keeps their clients.
- Smaller entry points exist for the Soroban parts: `@stellar/stellar-sdk/rpc` for the RPC client only and `@stellar/stellar-sdk/contract` for contract interaction only. Use them when a page needs only those.
- Don't rely on this for size. Measure with your bundler's analyser, because the result depends on the SDK version, your bundler and your target.
