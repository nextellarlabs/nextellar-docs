# Complete Hook Reference with Edge Case Coverage

This document serves as the authoritative, end-to-end reference for every React hook provided by Nextellar. It details input signatures, return types, expected runtime errors, race condition mitigations, unmount lifecycle behaviors, and concrete code patterns for edge-case resilience.

---

## 1. useStellarWallet

Manages wallet connectivity, account key state, balances, and classic payments.

### Signature & Inputs

```typescript
function useStellarWallet(
  horizonUrl?: string,
  network?: string
): StellarWalletState;
```

### Outputs & Return Values

```typescript
interface StellarWalletState {
  connected: boolean;
  publicKey?: string;
  walletName?: string;
  balances: Balance[];
  connect: () => Promise<void>;
  disconnect: () => void;
  refreshBalances: () => Promise<void>;
  sendPayment?: (
    options: PaymentOptions
  ) => Promise<Horizon.HorizonApi.SubmitTransactionResponse>;
}
```

### Error Scenarios & Edge Cases

- Connection errors are logged and rethrown from `connect()`.
- A failed account lookup leaves the wallet connected with an empty balance list.
- `sendPayment` is `undefined` until a wallet is connected.

### Race Condition & Unmount Handling

- **Race Condition**: A connection sequence counter prevents an older pending connection from overwriting a newer selection or disconnect.
- **Unmount Behavior**: The hook does not implement a dedicated mounted-state guard; avoid initiating new UI actions after unmount.

### Worked Edge Case Example

```tsx
import React, { useState } from 'react';
import { useStellarWallet } from '@/hooks/useStellarWallet';

export function WalletConnectEdgeCaseHandler() {
  const { connected, publicKey, connect, disconnect, refreshBalances } =
    useStellarWallet();
  const [message, setMessage] = useState<string | null>(null);

  const handleConnect = async () => {
    try {
      await connect();
      setMessage('Wallet connected.');
    } catch (error) {
      setMessage(error instanceof Error ? error.message : 'Connection failed.');
    }
  };

  return (
    <div>
      {message && <p role="status">{message}</p>}
      {!connected ? (
        <button onClick={() => void handleConnect()}>Connect Wallet</button>
      ) : (
        <div>
          <p>Connected Key: {publicKey}</p>
          <button onClick={() => void refreshBalances()}>
            Refresh balances
          </button>
          <button onClick={disconnect}>Disconnect</button>
        </div>
      )}
    </div>
  );
}
```

## 2. useStellarBalances

Tracks XLM and native/custom Stellar token balances for a given public key with reactive updates and optional polling.

### Signature & Inputs

```typescript
export interface BalanceOptions {
  horizonUrl?: string;
  autoRefresh?: boolean;
  refreshIntervalMs?: number;
}

export interface AssetBalance {
  asset_type: 'native' | 'credit_alphanum4' | 'credit_alphanum12';
  asset_code?: string;
  asset_issuer?: string;
  balance: string;
  limit?: string;
}

export function useStellarBalances(
  publicKey: string | null,
  options?: BalanceOptions
): {
  balances: AssetBalance[];
  loading: boolean;
  error: Error | null;
  refresh: () => Promise<void>;
};
```

### Error Scenarios & Edge Cases

- **Unfunded Account (Horizon 404)**: The hook catches Horizon 404 and returns `balances: []` without setting an error.
- **Malformed Public Key**: Invalid G-address formatting results in an instant validation error before making HTTP queries.
- **Horizon Rate Limit (429)**: The request error is stored in `error`; polling continues at the configured interval.

### Race Condition & Unmount Handling

- **Request Coordination**: A module-level guard skips duplicate fetches while a request is in flight. Requests are not aborted when the key changes.
- **Unmount Behavior**: Polling timers are cleared during effect cleanup; in-flight Horizon requests are not aborted.

### Worked Edge Case Example

```tsx
import React from 'react';
import { useStellarBalances } from '@/hooks/useStellarBalances';

export function UserBalanceDisplay({
  accountId,
}: {
  accountId: string | null;
}) {
  const { balances, loading, error, refresh } = useStellarBalances(accountId, {
    pollIntervalMs: 10000,
  });

  if (!accountId) return <div>No account provided.</div>;
  if (loading && balances.length === 0) return <div>Loading balances...</div>;

  if (error) {
    return (
      <div>
        <p className="error-box">Failed to fetch balances: {error.message}</p>
        <button onClick={refresh}>Retry</button>
      </div>
    );
  }

  if (balances.length === 0) {
    return <div>Account {accountId} is unfunded or has 0 assets.</div>;
  }

  return (
    <ul>
      {balances.map((b, idx) => (
        <li key={idx}>
          {b.asset_type === 'native' ? 'XLM' : b.asset_code}: {b.balance}
        </li>
      ))}
    </ul>
  );
}
```

## 3. useStellarPayment

Helper hook to construct, simulate, and submit Stellar payment operations.

### Signature & Inputs

```typescript
export interface PaymentParams {
  destination: string;
  amount: string;
  assetCode?: string; // Defaults to native XLM
  assetIssuer?: string;
  memo?: string;
}

export function useStellarPayment(options?: {
  horizonUrl?: string;
  networkPassphrase?: string;
}): {
  buildPaymentXDR: (
    fromPublicKey: string,
    params: PaymentParams
  ) => Promise<string>;
  submitPayment: (
    signedXdr: string
  ) => Promise<{ hash: string; ledger: number }>;
  submitting: boolean;
  error: Error | null;
};
```

### Error Scenarios & Edge Cases

- **Insufficient Reserve**: The sending account does not maintain the minimum required Stellar base reserve (0.5 XLM per entry + base reserve).
- **OpNoDestination**: Sending custom tokens or XLM to a destination account that does not exist and needs a `createAccount` operation instead.
- **Double Submit**: User double-clicks the pay button. Guarded by internal `submitting` status flag.

### Race Condition & Unmount Handling

- **Race Condition**: Prevents submission of outdated transaction XDRs if payment parameters are updated while a prior build operation was pending.
- **Unmount Behavior**: Transaction submission to Horizon continues on the server side, but unmounted components avoid invoking post-submit state callbacks.

### Worked Edge Case Example

```tsx
import React, { useState } from 'react';
import { useStellarPayment } from '@/hooks/useStellarPayment';
import { useStellarWallet } from '@/hooks/useStellarWallet';

export function SendPaymentForm() {
  const { publicKey, signTransaction } = useStellarWallet();
  const { buildPaymentXDR, submitPayment, submitting, error } =
    useStellarPayment();
  const [recipient, setRecipient] = useState('');
  const [amount, setAmount] = useState('');
  const [txHash, setTxHash] = useState<string | null>(null);

  const handlePay = async (e: React.FormEvent) => {
    e.preventDefault();
    if (!publicKey || submitting) return;

    try {
      const unsignedXdr = await buildPaymentXDR(publicKey, {
        destination: recipient,
        amount,
      });
      const signedXdr = await signTransaction(unsignedXdr);
      const res = await submitPayment(signedXdr);
      setTxHash(res.hash);
    } catch (err) {
      console.error('Payment failure:', err);
    }
  };

  return (
    <form onSubmit={handlePay}>
      <input
        placeholder="G..."
        value={recipient}
        onChange={(e) => setRecipient(e.target.value)}
      />
      <input
        placeholder="10.0"
        value={amount}
        onChange={(e) => setAmount(e.target.value)}
      />
      <button type="submit" disabled={submitting || !publicKey}>
        {submitting ? 'Processing Payment...' : 'Send XLM'}
      </button>
      {error && <p className="error">Payment Error: {error.message}</p>}
      {txHash && <p className="success">Success! Tx Hash: {txHash}</p>}
    </form>
  );
}
```

## 4. useTrustlines

Query existing asset trustlines and generate change-trust transaction XDRs for user wallets.

### Signature & Inputs

```typescript
export interface Trustline {
  asset_code: string;
  asset_issuer: string;
  balance: string;
  limit: string;
}

export function useTrustlines(
  publicKey: string | null,
  options?: { horizonUrl?: string }
): {
  trustlines: Trustline[];
  hasTrustline: (assetCode: string, issuer: string) => boolean;
  buildChangeTrustXDR: (params: {
    assetCode: string;
    assetIssuer: string;
    limit?: string;
  }) => Promise<string>;
  loading: boolean;
  error: Error | null;
  refresh: () => Promise<void>;
};
```

### Error Scenarios & Edge Cases

- **Lack of Reserve for Trustline**: Account requires an additional 0.5 XLM reserve per trustline. If balance is below minimum, transaction build or submit fails with `op_low_reserve`.
- **Invalid Asset Code / Issuer**: Passing non-existent issuer public keys returns validation error prior to XDR generation.

### Race Condition & Unmount Handling

- **Race Condition**: If a trustline transaction is submitted and confirmed, invoking `refresh()` immediately re-syncs state; pending inflight refreshes are deduplicated.
- **Unmount Behavior**: AbortController handles component unmounting mid-query.

## 5. useSorobanContract

Interact with Soroban smart contracts — simulate contract methods and invoke transactions.

### Signature & Inputs

```typescript
export function useSorobanContract(
  contractId: string,
  options?: { rpcUrl?: string; networkPassphrase?: string }
): {
  simulateContract: (
    method: string,
    args?: Record<string, any>
  ) => Promise<any>;
  invokeContract: (
    method: string,
    args?: Record<string, any>
  ) => Promise<{ hash: string; result: any }>;
  loading: boolean;
  error: Error | null;
};
```

### Error Scenarios & Edge Cases

- **Contract Panic / Host Error**: Contract simulation fails with error code (e.g., storage subkey missing, `require_auth` failure, integer overflow). The hook extracts exact panic message from RPC simulation result.
- **Storage TTL Expiry**: Attempting to interact with an archived Soroban contract instance without restoring instance storage first.

### Worked Edge Case Example

```tsx
import React, { useState } from 'react';
import { useSorobanContract } from '@/hooks/useSorobanContract';

export function ContractCallComponent() {
  const { invokeContract, loading, error } = useSorobanContract(
    'C1234...CONTRACT_ID'
  );
  const [output, setOutput] = useState<string | null>(null);

  const handleExecute = async () => {
    try {
      const res = await invokeContract('deposit', { amount: 500 });
      setOutput(`Tx Hash: ${res.hash}`);
    } catch (err: any) {
      if (err.message?.includes('HostError')) {
        console.error('Soroban VM panic:', err);
      }
    }
  };

  return (
    <div>
      <button onClick={handleExecute} disabled={loading}>
        {loading ? 'Invoking...' : 'Execute Soroban Call'}
      </button>
      {error && <p className="error">Contract Error: {error.message}</p>}
      {output && <p className="output">{output}</p>}
    </div>
  );
}
```

## Additional Edge Cases

These cases come up in real apps once hooks are combined, and they are not tied to one hook's signature. Each one lists the symptom, why it happens, and how to mitigate it.

### 1. Trustline Removal With a Non-Zero Balance (`useTrustlines`)

**Symptom:** Submitting a change-trust with `limit: '0'` fails with `op_invalid_limit`.

**Cause:** Stellar only deletes a trustline once the account's balance for that asset is exactly `0`. Open DEX offers that sell the asset (or buying liabilities against it) also block removal.

**Mitigation:** Disable the remove action until the balance is `0`, and tell the user to send, swap, or burn the remainder first. Cancel any open offers for the asset before removing it.

```tsx
const tl = trustlines.find(
  (t) => t.asset_code === code && t.asset_issuer === issuer
);
const canRemove = !!tl && Number(tl.balance ?? '0') === 0;

<button disabled={!canRemove} onClick={() => removeTrustline(code, issuer)}>
  Remove {code}
</button>;
```

### 2. Stale Sequence Number After Concurrent Submits (`useStellarPayment`, `useTrustlines`)

**Symptom:** The second of two transactions built back-to-back fails with `tx_bad_seq`.

**Cause:** Each `build*XDR` call loads the account and reads its current sequence number. If two XDRs are built before the first one lands, both use the same sequence number, and only the first can succeed.

**Mitigation:** Serialize submissions per account. Build the next XDR only after the previous one is confirmed, and on `tx_bad_seq` rebuild (don't resubmit) the transaction so it picks up the fresh sequence number.

```tsx
const queue = useRef(Promise.resolve());

const enqueue = (task: () => Promise<void>) => {
  queue.current = queue.current.then(task, task);
  return queue.current;
};

// Each task builds, signs, and submits one transaction in order.
enqueue(async () => {
  const xdr = await buildPaymentXDR({ from, to, amount, asset: 'XLM' });
  const signed = await sign(xdr);
  await submitSignedXDR(signed);
});
```

### 3. Transaction Expired While Waiting for a Signature (`useStellarPayment`, `useSorobanContract`)

**Symptom:** Submission fails with `tx_too_late` after the user left the wallet popup open for a while.

**Cause:** Built transactions carry a time bound. If the user takes longer than that window to approve, the signed XDR has already expired by the time it reaches the network.

**Mitigation:** Treat `tx_too_late` as recoverable. Rebuild the XDR and ask for a fresh signature instead of showing a generic failure. Build as late as possible, immediately before opening the wallet prompt, not when the form first renders.

```tsx
const result = await submitSignedXDR(signed);
if (!result.success && result.error?.includes('tx_too_late')) {
  setStatus('The signature expired. Please approve the transaction again.');
  return retryFromBuild();
}
```

### 4. Network Switch With Cached Data (`useStellarBalances`, `useTrustlines`, `useTransactionHistory`)

**Symptom:** After switching `WalletProvider` from Testnet to Mainnet, the UI briefly shows Testnet balances, trustlines, or history next to Mainnet account details.

**Cause:** Hooks keep their last successful result until the next fetch resolves. Changing `horizonUrl` triggers a refetch but doesn't clear the previous network's data first.

**Mitigation:** Key data-owning components by network so React remounts them with empty state, and pass `network` explicitly to hooks that build transactions (`useTrustlines` does not inherit it from the provider).

```tsx
<AccountPanel key={network} publicKey={publicKey} network={network} />
```

### 5. Missed Events Across a Polling Gap (`useSorobanEvents`)

**Symptom:** After the tab has been in the background, or the device slept, some contract events never appear in the list.

**Cause:** Browsers throttle timers in background tabs, and Soroban RPC only keeps events for a limited ledger window. If the gap between polls is longer than that window, the old cursor points to events that have already been pruned.

**Mitigation:** Refresh when the page becomes visible again. If the hook reports a recovery or cursor error, reconcile from contract state (for example, re-read balances with `useSorobanContract`) instead of relying on the event stream alone.

```tsx
useEffect(() => {
  const onVisible = () => {
    if (document.visibilityState === 'visible') refresh();
  };
  document.addEventListener('visibilitychange', onVisible);
  return () => document.removeEventListener('visibilitychange', onVisible);
}, [refresh]);
```

## Summary Matrix of Edge Case Protections

| Hook                    | Primary Edge Case      | Mitigation Strategy                                    |
| ----------------------- | ---------------------- | ------------------------------------------------------ |
| `useStellarWallet`      | User Popup Closure     | Graceful cancellation without infinite state locking   |
| `useStellarBalances`    | Unfunded Account (404) | Catch 404, return empty array with `isUnfunded` flag   |
| `useStellarPayment`     | Double Submission      | Synchronous `submitting` state lock guard              |
| `useTrustlines`         | Low Base Reserve       | Pre-calculate reserve requirements (0.5 XLM per entry) |
| `useSorobanContract`    | VM Panic / Out of Gas  | Parse host error stack & simulation return values      |
| `useSorobanEvents`      | Memory Leak / Polling  | Strict `useEffect` timer cleanup & AbortSignal         |
| `useOfferBook`          | Out-of-Order Pairs     | Input keying and cancellation of inflight queries      |
| `useTransactionHistory` | Rapid Pagination       | Cursor locking during active `loadMore()` operations   |
| `useTrustlines`         | Remove With Balance    | Gate removal on a zero balance and no open offers      |
| `useStellarPayment`     | Stale Sequence Number  | Serialize submits; rebuild XDR on `tx_bad_seq`         |
| `useStellarPayment`     | Expired Time Bounds    | Build just before signing; rebuild on `tx_too_late`    |
| `useStellarBalances`    | Network Switch         | Key components by network to drop stale data           |
| `useSorobanEvents`      | Polling Gap            | Refresh on visibility change; reconcile from state     |
