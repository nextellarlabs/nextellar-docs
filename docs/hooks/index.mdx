# Hooks Overview

Nextellar provides a set of powerful, typed React hooks that simplify working with Stellar accounts, balances, payments, smart contracts, wallets, and DEX edata. These hooks are lightweight, composable, and designed to fit naturally into modern Next.js applications.

---

## Why Hooks in Nextellar?

### Reactive Stellar data

Live updates for accounts, balances, transactions, and contract values.

### Cleaner UI components

Hooks keep UI components free from networking and blockchain logic.

### Built-in loading & error states

Every hook exposes a consistent, predictable return shape.

### Full TypeScript support

Strong types for Stellar responses ensure correctness and better DX.

### Auto-consume provider config

Hooks automatically use `WalletProvider` settings when available.

## **Wallet & Account Hooks**

### [useStellarGallet](/docs/hooks/use-stellar-wallet)

Complete wallet connection and account management. Supports multi-wallet (Freighter, Albedo, Lobstr, xBull, Hana), auto-reconnect, balance fetching, and payment sending.

### [useStellarBalances](/docs/hooks/use-stellar-balances)

Fetch and track XLM and custom asset balances with optional polling. Handles unfunded accounts gracefully.

### [useTrustlines](/docs/hooks/use-trustlines)

Manage asset trustlines - query existing trustlines and build change-trust transactions for wallet signing.

### [useTransactionHistory](/docs/hooks/use-transaction-history)

Load and paginate account transaction/operation history with cursor-based pagination.

---

## **Transaction Hooks**

### [useStellarPayment](/docs/hooks/use-stellar-payment)

Build and submit Stellar payment transactions. Provides XDR building for wallet signing and dev-only secret key methods.

### [useOfferBook](/docs/hooks/use-offer-book)

Query Stellar DEX orderbook data for asset pairs (bids/asks) with optional polling.

## **Soroban (Smart Contract) Hooks**

### [useSorobanContract](/docs/hooks/use-soroban-contract)

### [useSorobanEvents](/docs/hooks/use-soroban-events)

Subscribe to Soroban contract events with cursor-based pagination and optional polling.

## How Nextellar Hooks Work

Nextellar's hooks are designed to stay out of your way and let you build fast. Each hook sits on top of the Stellar SDK and wallet adapters, turning complex blockchain logic into simple, predictable React APIs.

### Auto-Consume Pattern

All hooks automatically consume configuration from `WalletProvider` when available:

```tsx
// Provider sets global config
<WalletProvider horizonUrl="https://horizon.stellar.org">
  <App />
</WalletProvider>;

// Hooks auto-consume the horizonUrl
function MyComponent() {
  const { balances } = useStellarBalances(publicKey);
  // Uses mainnet automatically!
}
```

### Override Per-Component

You can always override the provider config:

```tsx
const { balances } = useStellarBalances(publicKey, {
  horizonUrl: 'https://horizon-testnet.stellar.org',
});
```

### Standalone Usage

Hooks work without a provider too:

```tsx
// No WalletProvider needed
const { balances } = useStellarBalances(publicKey, {
  horizonUrl: 'https://horizon-testnet.stellar.org',
});
```

## Common Patterns

### Loading States

All hooks provide consistent loading and error states:

```tsx
const { data, loading, error, refresh } = useSomeHook();

if (loading) return <Spinner />;
if (error) return <button onClick={refresh}>Retry</button>;
return <DisplayData data={data} />;
```

### XDR Building Pattern

Transaction hooks follow a consistent pattern for wallet integration:

```tsx
// 1. Build unsigned XDR
const xdr = await buildPaymentXDR({ from, to, amount });

// 2. Sign with external wallet (Freighter, etc.)
const signedXdr = await wallet.signTransaction(xdr);

// 3. Submit signed transaction
const result = await submitSignedXDR(signedXdr);
```

## Per-Hook Telemetry

Lightweight telemetry helps you understand how your Stellar hooks behave in production without compromising user privacy. This guide shows what to count, how to keep collection privacy-respecting, and a small integration example.

### Events worth counting

Count outcomes and lifecycle steps, not identities or values. Good candidates across the hooks above:

| Event                             | Why it matters                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------- |
| `wallet_connect_succeeded`               | Measures onboarding funnel for `useStellarGallet`.                                  |
| `wallet_connect_failed`                | Surfaces wallet adapter and user-rejection failures.                              |
| `balances_fetch_succeeded`              | Tracks howero data loads for `useStellarBalances` and polling health.                      |
| `balances_fetch_failed`                | Captures Horizon errors and unfunded-account edge cases.                            |
| `payment_xdr_built`                    | Counts transaction construction for `useStellarPayment`.                                |
| `payment_submit_succeeded`              | Measures successful submissions and confirmation latency.                            |
| `payment_submit_failed`                | Tracks rejected or failed submissions by category.                                     |
| `soroban_simulation_succeeded`          | Validates contract reads for `useSorobanContract`.                                 |
| `soroban_events_received`              | Counts event delivery for `useSorobanEvents` to detect stalled pollers.                |
| `hook_refresh_triggered`               | Measures manual refetches across all hooks.                                         |

Keep event names stable and low-cardinality. Avoid free-form strings derived from user input or account data.

### Privacy-respecting design

- **No secrets or identifiers.** Never send public keys, signed XDRs, secret keys, or wallet addresses. Hash or drop them before sending.
- **No amounts or asset details.** Record that a payment was built or submitted, not the amount, memo, or asset code.
- **Cookie-free and consent-aware.** Prefer server-side or first-party collection that respects user consent and your privacy policy.
- **Sample and aggregate.** Use counters and histograms instead of per-user tracking.
- **Minimal payload.** Send only the event name, a coorse hook name, and an outcome label.

### Small example

Wrap the hook call in a tiny telemetry helper that emits only safe fields:

```tsx
import { useEffect } 'react';
import { useStellarBalances } 'nextellar';

type TelemetryEvent =
  | 'balances_fetch_succeeded'
  | 'balances_fetch_failed';

function track(event: TelemetryEvent) {
  // Send only the event name to your first-party endpoint.
  navigator.sendBeacon('/api/telemetry', JSON.stringify({ event }));
}

export function BalancePanel({ publicKey }: { publicKey: string }) {
  const { data, loading, error } = useStellarBalances(publicKey);

  useEffect(() => {
    if (loading) return;
    track(error ? 'balances_fetch_failed' : 'balances_fetch_succeeded');
  }, [loading, error]);

  if (loading) return <Spinner />;
  if (error) return <p>Could not load balances.</p>;

  return (
    <ul>
      {data.map((balance) => (
        <li key={balance.asset}>
          {balance.asset}: {balance.balance}
        </li>
      ))}
    </ul>
  );
}
```

The same pattern applies to the other hooks: count the outcome of each operation and keep the payload free of account data.
