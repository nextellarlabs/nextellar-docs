# Using Custom Endpoints (CLI & Hooks)

This guide covers how to configure and use custom Horizon and Soroban RPC endpoints in Nextellar projects. You can set endpoints via CLI flags, environment variables, hook configuration, and runtime composition.

## Quick Start

### Local Development (Testnet)

By default, Nextellar projects use Stellar's testnet endpoints. No configuration needed:

```bash
nextellar my-app
# Uses:
# - Horizon: https://horizon-testnet.stellar.org
# - Soroban RPC: https://soroban-testnet.stellar.org
```

### Production (Mainnet)

Switch to mainnet when deploying:

```bash
nextellar my-app \
  --horizon-url https://horizon.stellar.org \
  --soroban-url https://soroban-rpc.stellar.org
```

### Private Network

Use a custom endpoint for a private Stellar network:

```bash
nextellar my-app \
  --horizon-url http://private-stellar.local:8000 \
  --soroban-url http://private-stellar.local:8001
```

## Endpoint Options

### Stellar Public Endpoints

| Network | Horizon Endpoint                    | Soroban RPC Endpoint                |
| ------- | ----------------------------------- | ----------------------------------- |
| Testnet | `https://horizon-testnet.stellar.org` | `https://soroban-testnet.stellar.org` |
| Mainnet | `https://horizon.stellar.org`       | `https://soroban-rpc.stellar.org`   |

### Staging & Custom Endpoints

Nextellar supports any Horizon and Soroban RPC endpoint:

```
http://localhost:8000         (local Docker)
http://10.0.0.5:8000          (local network)
http://private-stellar.local:8000 (private domain)
https://custom.stellar.endpoint   (custom domain, HTTPS)
```

**Requirements:**

- Horizon endpoint must be accessible from your development machine
- Soroban RPC endpoint must be accessible from your development machine
- If behind a firewall, ensure CORS headers are set (for browser access)
- HTTPS is recommended for production deployments

## CLI-Level Configuration

CLI-level configuration affects scaffolding, upgrading, and validation commands. These settings are _not_ bundled into the generated app.

### Scaffolding with Custom Endpoints

Use `--horizon-url` and `--soroban-url` flags when creating a project:

```bash
# Create with custom endpoints
nextellar my-app \
  --horizon-url https://horizon.stellar.org \
  --soroban-url https://soroban-rpc.stellar.org
```

These flags also populate `.env.example` in the generated project, so developers know which endpoints to use.

### Environment Variables (CLI-Level)

You can also set CLI endpoints via environment variables:

```bash
export NEXTELLAR_HORIZON_URL="https://horizon.stellar.org"
export NEXTELLAR_SOROBAN_URL="https://soroban-rpc.stellar.org"

nextellar my-app
```

### Doctor Command with Custom Endpoints

Test endpoint connectivity:

```bash
# Check testnet endpoints
nextellar doctor

# Check mainnet endpoints
nextellar doctor \
  --horizon-url https://horizon.stellar.org \
  --soroban-url https://soroban-rpc.stellar.org

# Check custom endpoints
NEXTELLAR_HORIZON_URL="http://localhost:8000" nextellar doctor
```

**Output:**

```json
{
  "schemaVersion": 2,
  "horizonUrl": "https://horizon.stellar.org",
  "sorobanUrl": "https://soroban-rpc.stellar.org",
  "checks": [
    {
      "id": "horizon",
      "name": "Horizon API",
      "ok": true,
      "detail": "https://horizon.stellar.org (200)"
    },
    {
      "id": "soroban",
      "name": "Soroban RPC",
      "ok": true,
      "detail": "https://soroban-rpc.stellar.org (200)"
    }
  ]
}
```

## Application-Level Configuration

Application-level configuration affects the generated Nextellar app at runtime. These settings are exposed to browser code via `NEXT_PUBLIC_*` variables.

### Environment Variables in .env.local

Create a `.env.local` file in your project root:

```bash
# .env.local (development)
NEXT_PUBLIC_HORIZON_URL=https://horizon-testnet.stellar.org
NEXT_PUBLIC_SOROBAN_URL=https://soroban-testnet.stellar.org
```

Or for mainnet:

```bash
# .env.local (production)
NEXT_PUBLIC_HORIZON_URL=https://horizon.stellar.org
NEXT_PUBLIC_SOROBAN_URL=https://soroban-rpc.stellar.org
```

These variables are read by hooks at runtime and passed to Horizon and Soroban RPC.

### Post-Scaffolding Configuration

If you scaffolded with testnet endpoints but want to switch to mainnet later:

1. **Update `.env.local`:**

```bash
NEXT_PUBLIC_HORIZON_URL=https://horizon.stellar.org
NEXT_PUBLIC_SOROBAN_URL=https://soroban-rpc.stellar.org
NEXT_PUBLIC_NETWORK=PUBLIC
```

2. **Restart the dev server:**

```bash
npm run dev  # or yarn dev, pnpm dev
```

3. **Verify the change:**

Check the Network tab in browser DevTools. API calls should now go to `https://horizon.stellar.org` instead of testnet.

### Deployment Configuration

For production deployments, set environment variables in your hosting provider:

**Vercel:**

```bash
vercel env add NEXT_PUBLIC_HORIZON_URL
# Prompts: https://horizon.stellar.org
vercel env add NEXT_PUBLIC_SOROBAN_URL
# Prompts: https://soroban-rpc.stellar.org
```

**Netlify:**

```toml
# netlify.toml
[build]
  environment = { NEXT_PUBLIC_HORIZON_URL = "https://horizon.stellar.org", NEXT_PUBLIC_SOROBAN_URL = "https://soroban-rpc.stellar.org" }
```

**AWS Amplify:**

```yaml
# amplify.yml
version: 1
env:
  variables:
    NEXT_PUBLIC_HORIZON_URL: https://horizon.stellar.org
    NEXT_PUBLIC_SOROBAN_URL: https://soroban-rpc.stellar.org
```

## Hook-Level Configuration

Hooks auto-consume endpoints from your application configuration, but also allow per-call overrides.

### Auto-Consume from Context

Hooks read `NEXT_PUBLIC_HORIZON_URL` and `NEXT_PUBLIC_SOROBAN_URL` from the `WalletProvider` context:

```tsx
import { useStellarWallet } from '@/hooks';

export function MyComponent() {
  // Automatically uses NEXT_PUBLIC_HORIZON_URL and NEXT_PUBLIC_SOROBAN_URL
  const { publicKey, balances } = useStellarWallet();

  return <div>Connected: {publicKey}</div>;
}
```

### Per-Call Overrides

Override the default endpoints for a specific hook call:

```tsx
import { useStellarWallet } from '@/hooks';

export function TestnetDisplay() {
  const { balances } = useStellarWallet({
    horizonUrl: 'https://horizon-testnet.stellar.org',
    // Uses testnet, ignoring NEXT_PUBLIC_HORIZON_URL
  });

  return <div>Testnet Balance: {balances[0]?.balance}</div>;
}

export function MainnetDisplay() {
  const { balances } = useStellarWallet({
    horizonUrl: 'https://horizon.stellar.org',
    // Uses mainnet, ignoring NEXT_PUBLIC_HORIZON_URL
  });

  return <div>Mainnet Balance: {balances[0]?.balance}</div>;
}
```

### Custom Hook with Endpoint Support

When writing a custom hook, follow this pattern:

```tsx
import { useWalletContext } from '@/context/WalletContext';

interface UseAssetPricingOptions {
  horizonUrl?: string;     // Allow per-call override
  pollingInterval?: number;
}

export function useAssetPricing(
  assetCode: string,
  options: UseAssetPricingOptions = {}
) {
  const { horizonUrl: providerUrl } = useWalletContext();

  // 1. Use per-call override
  // 2. Fall back to provider (from context)
  // 3. Fall back to default
  const horizonUrl =
    options.horizonUrl ??
    providerUrl ??
    'https://horizon-testnet.stellar.org';

  // ... rest of hook implementation
}
```

### Configuration Context

For more complex scenarios, create a custom hook to wrap endpoint logic:

```tsx
// src/hooks/useEndpoints.ts
import { useWalletContext } from '@/context/WalletContext';

export interface EndpointConfig {
  horizonUrl: string;
  sorobanUrl: string;
  network: 'TESTNET' | 'PUBLIC';
}

export function useEndpoints(): EndpointConfig {
  const { horizonUrl, sorobanUrl } = useWalletContext();

  return {
    horizonUrl: horizonUrl || 'https://horizon-testnet.stellar.org',
    sorobanUrl: sorobanUrl || 'https://soroban-testnet.stellar.org',
    network: horizonUrl?.includes('mainnet')
      ? 'PUBLIC'
      : 'TESTNET',
  };
}
```

Then use it in other hooks:

```tsx
import { useEndpoints } from './useEndpoints';

export function useAssetPricing(assetCode: string) {
  const { horizonUrl } = useEndpoints();

  // Use horizonUrl in your fetch logic
}
```

## Worked Example: Private Network

This example sets up a Nextellar project to use a private Stellar network running in Docker.

### Step 1: Start a Private Stellar Network

Use Docker Compose to run a local Stellar instance:

```yaml
# docker-compose.yml
version: '3.8'
services:
  stellar:
    image: stellar/quickstart:latest
    environment:
      - NETWORK_TYPE=standalone
      - ENABLE_CORE_DIAGNOSTICS=true
    ports:
      - '8000:8000'  # Horizon
      - '8001:8001'  # Soroban RPC
      - '11626:11626' # Core
```

Start it:

```bash
docker-compose up -d
```

Verify connectivity:

```bash
curl http://localhost:8000/
# Should return Horizon info

curl http://localhost:8001/rpc
# Should return Soroban RPC info
```

### Step 2: Scaffold with Custom Endpoints

Create a Nextellar project pointing to your local network:

```bash
nextellar my-local-app \
  --horizon-url http://localhost:8000 \
  --soroban-url http://localhost:8001 \
  --network TESTNET \
  --with-contracts
```

This generates `.env.example`:

```bash
# .env.example
NEXT_PUBLIC_HORIZON_URL=http://localhost:8000
NEXT_PUBLIC_SOROBAN_URL=http://localhost:8001
NEXT_PUBLIC_NETWORK=TESTNET
```

### Step 3: Create `.env.local`

```bash
cp .env.example .env.local
```

### Step 4: Verify Connection

Run `nextellar doctor` to confirm endpoints are reachable:

```bash
NEXTELLAR_HORIZON_URL=http://localhost:8000 NEXTELLAR_SOROBAN_URL=http://localhost:8001 nextellar doctor
```

Expected output:

```json
{
  "checks": [
    {
      "id": "horizon",
      "name": "Horizon API",
      "ok": true,
      "detail": "http://localhost:8000 (200)"
    },
    {
      "id": "soroban",
      "name": "Soroban RPC",
      "ok": true,
      "detail": "http://localhost:8001 (200)"
    }
  ]
}
```

### Step 5: Start Development

```bash
npm run dev
```

Your app now connects to the local Stellar network.

### Step 6: Switch Between Networks

Switch back to testnet by updating `.env.local`:

```bash
# .env.local
NEXT_PUBLIC_HORIZON_URL=https://horizon-testnet.stellar.org
NEXT_PUBLIC_SOROBAN_URL=https://soroban-testnet.stellar.org
```

Then restart `npm run dev`.

## Troubleshooting

### Horizon Connection Error

**Error:** `Error: fetch failed — ECONNREFUSED`

**Cause:** Horizon endpoint is unreachable.

**Solution:**

1. Verify the endpoint is correct:

```bash
curl https://horizon-testnet.stellar.org/
```

2. Check firewall rules (if using private network)

3. Verify the endpoint is running (if local):

```bash
docker-compose ps
# Check that stellar service is running
```

### CORS Error in Browser

**Error:** `Access to XMLHttpRequest at '...' blocked by CORS policy`

**Cause:** Horizon endpoint is not configured for cross-origin requests.

**Solution:**

- For Stellar's public endpoints, CORS is enabled.
- For custom endpoints, ensure CORS headers are set:

```
Access-Control-Allow-Origin: *
```

Or use a CORS proxy in development:

```bash
# .env.local
NEXT_PUBLIC_HORIZON_URL=https://cors-anywhere.herokuapp.com/https://your-endpoint.com
```

### Soroban RPC 404 Error

**Error:** `404 Not Found` when calling `useSorobanClient`

**Cause:** Soroban RPC endpoint is not configured or is pointing to a Horizon endpoint.

**Solution:**

- Verify `NEXT_PUBLIC_SOROBAN_URL` is set to a Soroban RPC endpoint (not Horizon)
- Check the endpoint in DevTools Network tab
- Restart the dev server after changing `.env.local`

### Endpoint Works Locally but Not in Production

**Cause:** Environment variables not set in production environment.

**Solution:**

1. Verify environment variables in your hosting provider's dashboard
2. Check the build logs to confirm variables were injected
3. Restart the deployment after updating variables
