# Deploying a Nextellar App

A Nextellar project is a standard Next.js app with Stellar hooks and wallet integration. Today, the supported way to put it in front of users is the same as for any Next.js app: deploy to Vercel or a self-hosted Node server.

The `nextellar deploy` command does **not** publish your app anywhere yet. It validates the project and produces a local bundle for a future Nextellar Cloud platform. This guide separates the two.

## Deploy the app (supported path)

### 1. Build and test locally

```bash
npm install
npm run build
npm start
```

### 2. Configure environment variables

Every scaffold ships an `.env.example`. Copy it to `.env.local`, then fill in the values for your target network:

```bash
cp .env.example .env.local
```

| Variable                    | Purpose                                             |
| --------------------------- | --------------------------------------------------- |
| `NEXT_PUBLIC_HORIZON_URL`   | Horizon endpoint (testnet or public)                |
| `NEXT_PUBLIC_SOROBAN_URL`   | Soroban RPC endpoint                                |
| `NEXT_PUBLIC_NETWORK`       | `TESTNET` or `PUBLIC`                               |
| `NEXT_PUBLIC_WALLETS`       | Optional comma-separated wallet list                |
| `NEXT_PUBLIC_CONTRACT_ID`   | Optional, added after deploying contracts           |
| `NEXT_PUBLIC_APP_NAME`      | Display name for the app                            |

See the [Environment Variables Reference](/docs/cli/env-vars-reference) for the full list. Never commit `.env.local` or secret keys — set production values in your host's environment variable settings.

### 3. Deploy to Vercel

1. Push the project to a Git repository.
2. Import it in Vercel; the Next.js preset is detected automatically.
3. Add the same variables from `.env.local` under **Settings → Environment Variables**.
4. Deploy. Preview deployments are created for pull requests.

### 4. Self-host instead

Build the app (`npm run build`), then run `npm start` on a Node server with the same environment variables. Keep the generated `.next` output in the deployed artifact.

For a longer walkthrough covering custom domains, monitoring and rollback, see [Production Deployment (Vercel + Cloud)](/docs/guides/production-deployment-vercel-nextellar-cloud). The "Nextellar Cloud" sections of that guide describe planned infrastructure, not a currently available upload target.

## What `nextellar deploy` does today

`nextellar deploy` is a local validation and packaging step. It never uploads or publishes the bundle, and it does not contact a Nextellar service.

```bash
npm run build
nextellar deploy
```

Prerequisite: the command checks for a production build at `.next/` and fails with `Missing production build (.next). Run 'npm run build' first.` if it is absent.

The command validates that:

- `package.json` exists in the current directory (run it from the project root),
- `next` is listed in `dependencies` or `devDependencies`,
- `.next/` exists.

On success it prints the project root and whether a `/contracts` directory was detected, then creates a gzip tarball at:

```text
.nextellar/deploy/<project-name>-<timestamp>.tar.gz
```

The bundle contains the project directory with these exclusions:

- `node_modules`
- `.git`
- `.next/cache`
- `.nextellar/deploy` (so bundles do not accumulate inside each other)

A metadata file is written to `.nextellar/deploy/latest-bundle.json` with the bundle path, size, contract detection and creation time.

Finally the command prints:

```text
Nextellar Cloud is coming soon. For now, deploy with Vercel: npx vercel
```

Upload, log streaming and deployment URLs are explicit TODOs in the CLI. Treat the tarball as an artifact for local inspection or for a future platform, not as a deployment.

### Dry run

```bash
nextellar deploy --dry-run
```

This runs the same validation and prints the bundle path that would be created plus the exclusion list, but writes no bundle. It is safe to use in CI to check that a project is deployable.

`--dry-run` is the only option the command currently supports; see [CLI Commands](/docs/cli/commands#nextellar-deploy) for the command reference.

## Choosing between the two

| Goal                                  | Use                                  |
| ------------------------------------- | ------------------------------------ |
| Put a scaffolded app online today     | Vercel or a self-hosted Node server  |
| Verify a project is packaged cleanly  | `nextellar deploy --dry-run`         |
| Produce a local artifact for inspection | `nextellar deploy` after a build  |
| Upload to Nextellar Cloud             | Not available yet                    |
