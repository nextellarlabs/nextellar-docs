# Complete Pre-Authorized Transactions Workflow Guide

Pre-authorized transactions on Stellar allow an account to authorize a future transaction in advance without revealing or storing secret keys. By using a **Hash(X) Pre-Auth Signer**, the SHA-256 hash of a pre-built transaction XDR is registered as a valid signer on a Stellar account with a specific weight.

Once the pre-authorized transaction is submitted and validated on-chain, the network automatically removes the hash from the account's signer list, ensuring one-time execution.

---

## 1. Mechanics of Pre-Authorized Transactions

```
[ 1. Build Future Tx XDR ] ──> [ 2. Hash Tx (SHA-256) ] ──> [ 3. Add PreAuthTx Signer ] ──> [ 4. Execute Future Tx ]
```

1. **Construct Future Transaction**: Build the transaction XDR (e.g. transfer of funds, account merge, or threshold update) with specified sequence number and time bounds.
2. **Compute SHA-256 Hash**: Derive the exact 32-byte transaction hash.
3. **Add Signer**: Execute a `SetOptions` operation on the account, adding `signer.preAuthTx` with weight matching operational threshold (e.g. 1).
4. **Submit Transaction**: Anyone can submit the original pre-built transaction later; Stellar Horizon validates that the transaction hash matches the authorized signer.

## 2. Step-by-Step Sequence & Code Implementation

Below is a complete TypeScript workflow using `@stellar/stellar-sdk` and Nextellar integration helpers.

### Step 1: Create Future Transaction & Calculate Hash

```typescript
import {
  TransactionBuilder,
  Account,
  Keypair,
  Networks,
  Operation,
} from '@stellar/stellar-sdk';

export async function createPreAuthTransaction(
  sourcePublicKey: string,
  currentSequenceNumber: string,
  destinationPublicKey: string,
  amountXlm: string
) {
  // 1. Instantiate source account
  const sourceAccount = new Account(sourcePublicKey, currentSequenceNumber);

  // 2. Build future transaction (e.g. payment or withdrawal)
  const futureTx = new TransactionBuilder(sourceAccount, {
    fee: '100',
    networkPassphrase: Networks.TESTNET,
    timebounds: {
      minTime: 0,
      maxTime: Math.floor(Date.now() / 1000) + 86400 * 30, // Valid for 30 days
    },
  })
    .addOperation(
      Operation.payment({
        destination: destinationPublicKey,
        asset: Asset.native(),
        amount: amountXlm,
      })
    )
    .build();

  // 3. Obtain transaction hash (SHA-256 of signature payload)
  const preAuthTxHash = futureTx.hash(); // Buffer / Uint8Array (32 bytes)
  const preAuthTxXdr = futureTx.toXDR();

  return { futureTx, preAuthTxHash, preAuthTxXdr };
}
```

### Step 2: Add Hash(X) Signer to Stellar Account

```typescript
import {
  TransactionBuilder,
  Account,
  Networks,
  Operation,
} from '@stellar/stellar-sdk';

export async function buildAddPreAuthSignerXDR(
  accountPublicKey: string,
  currentSequence: string,
  preAuthTxHash: Buffer
) {
  const account = new Account(accountPublicKey, currentSequence);

  // Add the pre-authorized transaction hash as a signer
  const setupTx = new TransactionBuilder(account, {
    fee: '100',
    networkPassphrase: Networks.TESTNET,
  })
    .addOperation(
      Operation.setOptions({
        signer: {
          preAuthTx: preAuthTxHash,
          weight: 1, // Matches medium threshold
        },
      })
    )
    .build();

  return setupTx.toXDR();
}
```

## 3. End-to-End Execution Example

```tsx
import React, { useState } from 'react';
import { useStellarWallet } from '@/hooks/useStellarWallet';
import { useStellarPayment } from '@/hooks/useStellarPayment';

export function PreAuthWorkflowManager() {
  const { publicKey, signTransaction } = useStellarWallet();
  const { submitPayment } = useStellarPayment();
  const [savedPreAuthXdr, setSavedPreAuthXdr] = useState<string | null>(null);
  const [status, setStatus] = useState<string>('');

  // 1. Build and Authorize PreAuth Tx
  const handleSetupPreAuth = async () => {
    if (!publicKey) return;
    try {
      setStatus('Building future transaction...');
      const targetSeq = '1000000000000000'; // Fetch latest sequence from Horizon in practice

      const { preAuthTxHash, preAuthTxXdr } = await createPreAuthTransaction(
        publicKey,
        targetSeq,
        'GDESTINATION...PUBLIC_KEY',
        '50.0'
      );

      // Save pre-auth transaction XDR locally or in storage for future broadcast
      setSavedPreAuthXdr(preAuthTxXdr);

      setStatus('Building SetOptions transaction to authorize Hash(X)...');
      const setupXdr = await buildAddPreAuthSignerXDR(
        publicKey,
        targetSeq,
        preAuthTxHash
      );

      setStatus('Please sign SetOptions in wallet...');
      const signedSetupXdr = await signTransaction(setupXdr);
      await submitPayment(signedSetupXdr);

      setStatus('PreAuth Signer successfully added to account!');
    } catch (err: any) {
      setStatus(`Setup failed: ${err.message}`);
    }
  };

  // 2. Execute PreAuth Transaction without requiring wallet key signatures!
  const handleExecutePreAuth = async () => {
    if (!savedPreAuthXdr) return;
    try {
      setStatus('Broadcasting pre-authorized transaction to Horizon...');
      // The transaction is ALREADY authorized by its hash, no key signature needed!
      const res = await submitPayment(savedPreAuthXdr);
      setStatus(`Execution successful! Tx Hash: ${res.hash}`);
    } catch (err: any) {
      setStatus(`Execution failed: ${err.message}`);
    }
  };

  return (
    <div className="preauth-box">
      <h3>Pre-Authorized Transaction Workflow</h3>
      <p>{status}</p>
      <button onClick={handleSetupPreAuth}>
        1. Setup & Authorize PreAuth Hash
      </button>
      <button onClick={handleExecutePreAuth} disabled={!savedPreAuthXdr}>
        2. Execute PreAuth Tx
      </button>
    </div>
  );
}
```

## 4. Operational Requirements & Pitfalls

1. **Sequence Number Sensitivity**: A pre-authorized transaction relies on an exact sequence number. If any other transaction is submitted from the account prior to the pre-authorized transaction, its sequence number will be invalid, causing `tx_bad_seq`.
2. **One-Time Execution (Automatic Burn)**: Once executed, Horizon automatically deletes the `preAuthTx` signer entry. Re-submitting the exact same transaction will fail.
3. **Timebounds**: Always include reasonable `timebounds` to prevent stale transactions from remaining executable indefinitely.
