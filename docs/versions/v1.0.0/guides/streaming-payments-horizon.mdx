# Streaming Payments from Horizon

Horizon exposes most collection endpoints — payments, transactions, effects, operations, orderbook — as [server-sent event (SSE)](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events) streams. Instead of polling `/accounts/{id}/payments` on an interval, you open a long-lived connection and Horizon pushes new payments to you as they settle. This guide covers subscribing to the payments stream, resuming safely after a disconnect, and a small working example.

---

## How the streaming endpoint works

Any Horizon collection endpoint streams when requested with `Accept: text/event-stream`:

```
GET /accounts/{account}/payments?cursor=now
Accept: text/event-stream
```

Each event's `data` field is a JSON payment record — the same shape you'd get from the equivalent JSON response. The `@stellar/stellar-sdk` wraps this in a `.stream()` call so you rarely touch raw SSE directly.

## Subscription setup

```typescript
import { Server } from '@stellar/stellar-sdk';

const server = new Server('https://horizon-testnet.stellar.org');

const closeStream = server
  .payments()
  .forAccount('GABC...') // account to watch
  .cursor('now') // only payments from this point forward
  .stream({
    onmessage: (payment) => {
      console.log(`${payment.type} — ${payment.amount} ${payment.asset_type}`);
    },
    onerror: (error) => {
      console.error('Payment stream error:', error);
    },
  });

// Later, when the component unmounts or the watch is no longer needed:
closeStream();
```

`cursor('now')` starts the stream at the current ledger and ignores history — use `cursor('0')` if you want the stream to first replay all past payments before switching to live events.

## Reconnect handling

`.stream()` is backed by an `EventSource`, and Horizon's underlying transport will drop idle connections — typically after load balancer or proxy timeouts, well before any application-level error. Two things matter for correctness across a reconnect:

1. **The SDK does not automatically resume where it left off.** A raw `EventSource` retry reopens the _same_ request, but if you constructed the stream with `cursor('now')`, a reconnect re-evaluates "now" and you silently lose any payments that arrived during the gap.
2. **Track the last-seen `paging_token` yourself** and re-open the stream from that cursor rather than `'now'`, so a reconnect resumes exactly where it stopped instead of skipping or replaying events.

```typescript
function watchPayments(accountId: string, onPayment: (p: any) => void) {
  let cursor = 'now';
  let closeFn: () => void;

  function connect() {
    closeFn = server
      .payments()
      .forAccount(accountId)
      .cursor(cursor)
      .stream({
        onmessage: (payment) => {
          cursor = payment.paging_token; // persist progress
          onPayment(payment);
        },
        onerror: () => {
          // Horizon closed the connection — reconnect from the last cursor
          closeFn();
          setTimeout(connect, 1000);
        },
      });
  }

  connect();
  return () => closeFn();
}
```

> **Persist the cursor outside memory for long-running watchers.** If your process restarts (server redeploy, page reload), an in-memory cursor is lost and you fall back to `'now'`, missing anything that happened while you were down. Save the cursor to a database or `localStorage` after each event for watchers that must not miss payments.

## Minimal example

A self-contained watcher that logs incoming payments and survives reconnects:

```typescript
import { Server } from '@stellar/stellar-sdk';

const server = new Server('https://horizon-testnet.stellar.org');

function streamPayments(accountId: string) {
  let cursor = localStorage.getItem(`cursor:${accountId}`) ?? 'now';
  let stop: () => void;

  const connect = () => {
    stop = server
      .payments()
      .forAccount(accountId)
      .cursor(cursor)
      .stream({
        onmessage: (payment) => {
          cursor = payment.paging_token;
          localStorage.setItem(`cursor:${accountId}`, cursor);

          if (payment.type === 'payment') {
            console.log(`Received ${payment.amount} from ${payment.from}`);
          }
        },
        onerror: () => {
          stop();
          setTimeout(connect, 1000); // simple fixed-delay retry
        },
      });
  };

  connect();
  return () => stop();
}

const stopWatching = streamPayments('GABC...');
// stopWatching() to tear down
```

In a Nextellar app, prefer [useTransactionHistory](/docs/hooks/use-transaction-history) for UI-bound transaction lists — it already handles cursor-based pagination internally. Reach for a raw `.stream()` subscription like the one above when you need to react to payments as side effects (notifications, webhooks, background jobs) rather than render a list.
