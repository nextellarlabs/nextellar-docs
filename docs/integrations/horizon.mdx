# Stellar Horizon Integration

> **Source traceability:** Defaults and env placeholders are defined in Nextellar CLI scaffold templates (`.env.example`, `WalletProvider`, hooks) and `src/lib/scaffold.ts` (`{{HORIZON_URL}}`, `{{SOROBAN_URL}}`, network derivation). CLI flags `--horizon-url`/`--soroban-url` are validated by `src/lib/validate.ts`.

Nextellar uses the official `@stellar/stellar-sdk` to interact with Stellar's Horizon API. This integration powers account queries, balance fetching, payment transactions, and transaction history.

## What is Horizon?

Horizon is Stellar's HTTP API server that provides a RESTful interface to the Stellar network. It allows you to:

- Query account balances and details.
- Submit transactions.
- Fetch transaction history.
- Query the order book (DEX).
- Stream real-time updates.

## How Nextellar Uses Horizon

### Default Endpoints

Nextellar hooks default to Stellar's public Horizon servers:

| Network | URL                                   |
| ------- | ------------------------------------- |
| Testnet | `https://horizon-testnet.stellar.org` |
| Mainnet | `https://horizon.stellar.org`         |

### Configure a Custom Endpoint

Pass `--horizon-url` when scaffolding to replace the default public Horizon
endpoint:

```bash
npx nextellar my-app \
  --horizon-url https://horizon.example.com
```

The generated project writes the value to `NEXT_PUBLIC_HORIZON_URL`. Use an
endpoint for the same Stellar network as the wallet and network passphrase, and
pass that value to `WalletProvider` if you configure the provider manually:

```tsx
const horizonUrl = process.env.NEXT_PUBLIC_HORIZON_URL!;

<WalletProvider horizonUrl={horizonUrl}>
  <App />
</WalletProvider>;
```

Confirm that the custom endpoint is reachable before running the app:

```bash
npx nextellar doctor --horizon-url https://horizon.example.com
```

Use the Horizon server's base URL without an endpoint suffix such as
`/accounts`. If the server requires authentication headers, route requests
through a server-side proxy rather than exposing credentials in a
`NEXT_PUBLIC_` variable.

### Hooks That Use Horizon

| Hook                    | Horizon Operations                     |
| ----------------------- | -------------------------------------- |
| `useStellarBalances`    | `GET /accounts/{id}` - Fetch balances  |
| `useStellarPayment`     | `POST /transactions` - Submit payments |
| `useStellarWallet`      | Account queries and payments           |
| `useTransactionHistory` | `GET /accounts/{id}/operations`        |
| `useTrustlines`         | `POST /transactions` - ChangeTrust ops |
| `useOfferBook`          | `GET /order_book` - DEX queries        |

## Account Data Entries

An account can store up to 100 data entries, each with a value of up to 64 bytes. Each entry counts as a subentry and increases the account's minimum balance by one base reserve. The base reserve is set by the network.

## Using Horizon in Hooks

### With WalletProvider (Recommended)

Configure once at the provider level:

```tsx
<WalletProvider horizonUrl="https://horizon.stellar.org">
  <App /> {/* All hooks use mainnet Horizon */}
</WalletProvider>
```

### Per-Hook Override

Override for specific components:

```tsx
const { balances } = useStellarBalances(publicKey, {
  horizonUrl: 'https://horizon.stellar.org', // Use mainnet
});
```

### Standalone Usage

Use without WalletProvider:

```tsx
const { balances } = useStellarBalances(publicKey, {
  horizonUrl: 'https://horizon-testnet.stellar.org',
});
```

## Direct Horizon Usage

For advanced use cases, use the Stellar SDK directly:

```tsx
import { Horizon } from '@stellar/stellar-sdk';

const server = new Horizon.Server('https://horizon-testnet.stellar.org');

// Fetch account
const account = await server.accounts().accountId(publicKey).call();

// Fetch transactions
const transactions = await server
  .transactions()
  .forAccount(publicKey)
  .limit(10)
  .order('desc')
  .call();

// Load account for transaction building
const sourceAccount = await server.loadAccount(publicKey);
```

Horizon may still return the account's `inflation_destination` field. It is a historical, deprecated field that once nominated an account to receive inflation payouts; inflation operations have not been supported since Protocol 12, so the field has no effect.

## Transaction Building

Nextellar hooks build transactions using the Stellar SDK:

```tsx
import {
  TransactionBuilder,
  Operation,
  Asset,
  Networks,
  BASE_FEE,
} from '@stellar/stellar-sdk';

// Build a payment transaction
const transaction = new TransactionBuilder(sourceAccount, {
  fee: BASE_FEE,
  networkPassphrase: Networks.TESTNET,
})
  .addOperation(
    Operation.payment({
      destination: recipientAddress,
      asset: Asset.native(),
      amount: '10',
    })
  )
  .setTimeout(30)
  .build();
```

### Payment operation basics

A payment operation requires a destination account, an asset, and a positive amount. The operation source defaults to the transaction source, which must authorize the transaction. Common failures include `op_underfunded` (not enough balance), `op_no_destination` (the destination account does not exist), and `op_no_trust` or `op_line_full` when the recipient cannot receive an issued asset.

### SEP-29 memo requirement

SEP-29 applies when the destination account sets a `config.memo_required` data entry to `1`, as custodial accounts often do to credit deposits. Before submitting a `PAYMENT`, `PATH_PAYMENT_STRICT_SEND`, `PATH_PAYMENT_STRICT_RECEIVE`, or `MERGE_ACCOUNT` operation to that account, clients should load the destination and check the flag. If it is set, require a memo and prevent submission without one, checking each operation in a transaction with multiple operations. A missing memo is reported as `AccountRequiresMemoError`.

## Environment Variables

Scaffolded projects include Horizon and Soroban URL placeholders in `.env.example`. Configure them via environment variables:

```bash
## .env.local
NEXT_PUBLIC_HORIZON_URL=https://horizon.stellar.org
NEXT_PUBLIC_SOROBAN_URL=https://soroban-rpc.stellar.org
```

```tsx
// Access in your app
const horizonUrl = process.env.NEXT_PUBLIC_HORIZON_URL;
const sorobanUrl = process.env.NEXT_PUBLIC_SOROBAN_URL;
```

> **Mainnet switching:** `NEXT_PUBLIC_HORIZON_URL`/`NEXT_PUBLIC_SOROBAN_URL` control endpoint selection in scaffolded code. When switching to mainnet, also update network/passphrase configuration used by your wallet/provider and transaction builders so endpoint and network passphrase match.

## Error Handling

Horizon returns specific error codes. Hooks handle common ones:

| Error          | Meaning              | Hook Response                 |
| -------------- | -------------------- | ----------------------------- |
| 404            | Account not found    | Empty balances, `error` state |
| 400            | Bad request          | Validation error              |
| 429            | Rate limit exceeded  | Wait before retrying          |
| 504            | Timeout              | Network error                 |
| tx_bad_seq     | Sequence mismatch    | Retry needed                  |
| op_underfunded | Insufficient balance | Payment failed                |

```tsx
const { error, refresh } = useStellarBalances(publicKey);

if (error?.message.includes('404')) {
  return <p>Account not funded yet</p>;
}
```

Horizon commonly returns `429` after bursts of requests, frequent polling, or concurrent clients sharing an IP. Honor `Retry-After` when present; otherwise use exponential backoff with jitter and reduce request volume. Do not retry immediately. See [Rate Limiting Horizon Requests](/docs/guides/rate-limiting-horizon-requests) for more.

## Horizon Ingest Lag

Ingest lag is the gap between the latest ledger closed by Stellar Core and the latest ledger indexed by Horizon. Check the Horizon root endpoint (`GET /`) and compare `core_latest_ledger` with `history_latest_ledger`; their difference is the lag in ledgers.

## Rate Limiting

Stellar's public Horizon servers have rate limits. For production:

1. **Use polling sparingly** - Set `pollIntervalMs` to 10+ seconds
2. **Consider self-hosting** - Run your own Horizon instance
3. **Use caching** - Implement client-side caching

```tsx
const { balances } = useStellarBalances(publicKey, {
  pollIntervalMs: 15000, // Poll every 15 seconds
});
```
