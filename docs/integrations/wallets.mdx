# Wallet Integration

Nextellar uses [@creit.tech/stellar-wallets-kit](https://github.com/Creit-Tech/Stellar-Wallets-Kit) to provide seamless multi-wallet support. This integration enables connecting to Freighter, Albedo, Lobstr, and other Stellar wallets.

> **CLI Configuration:** For details on configuring wallet adapters during project scaffolding with the `--wallets` flag (including defaults and supported adapters), see [Wallet Configuration](/docs/cli/flags#wallet-configuration-wallets) in the CLI Flags reference.

## Supported Wallets

Nextellar supports the wallets below. A new project enables Freighter, Albedo,
and Lobstr by default; pass `--wallets` to enable others:

| Wallet        | Type              | Features                    |
| ------------- | ----------------- | --------------------------- |
| **Freighter** | Browser Extension | Most popular, full-featured |
| **Albedo**    | Web-based         | No installation required    |
| **Lobstr**    | Browser Extension | Mobile-friendly companion   |
| **xBull**     | Browser Extension | Advanced features           |
| **Hana**      | Browser Extension | Stellar ecosystem wallet    |
| **Ledger**    | Hardware (WebUSB) | Enable with `ledger`        |

The `walletconnect` option is covered on the [WalletConnect](/docs/integrations/walletconnect) page.

## Set Up xBull

1. Install xBull from the [official xBull site](https://xbull.app/) and unlock
   the extension.
2. Create a wallet or import an existing account. Back up the recovery phrase
   offline and never share it with your app.
3. In xBull, select the same network your Nextellar app uses. New Nextellar
   projects use Stellar Testnet by default.
4. Include the xBull adapter when scaffolding your project:

   ```bash
   npx nextellar my-app --wallets freighter,xbull
   ```

   In an existing project, confirm that `xBullModule` is imported and included
   in the `modules` array shown below.

5. Start the app, choose **Connect Wallet**, select **xBull**, and approve the
   site's connection request in the extension.
6. Verify that the public key shown by the app matches the active xBull account.
   Before signing a test transaction, also confirm that the app and xBull both
   show the same network.

If a new Testnet account has no balance, fund it with the steps in
[Testing (MSW)](/docs/integrations/testing#fund-a-stellar-testnet-account).

## How It Works

### Wallet Kit Configuration

The wallet kit is created lazily in `src/lib/stellar-wallet-kit.ts`. The modules
are chosen from the `--wallets` list written at scaffold time, and the network
(`TESTNET` or `PUBLIC`) comes from the scaffold-time network value unless you
pass one:

```typescript
const INJECTED_WALLETS: string[] = ['freighter', 'albedo', 'lobstr']; // set by --wallets

export const getKit = (network?: WalletNetwork): StellarWalletsKit => {
  // ...
  const modules = [];
  if (walletList.includes('freighter')) modules.push(new FreighterModule());
  if (walletList.includes('albedo')) modules.push(new AlbedoModule());
  if (walletList.includes('lobstr')) modules.push(new LobstrModule());
  if (walletList.includes('xbull')) modules.push(new xBullModule());
  if (walletList.includes('hana')) modules.push(new HanaModule());
  // ledger and walletconnect modules are added the same way
  // ...
};

// `kit` is a function that returns the kit instance
export const kit = (network?: WalletNetwork) => getKit(network);
```

### Connection Flow

1. User clicks "Connect Wallet" (via `WalletConnectButton` or custom UI)
2. Stellar Wallets Kit opens the wallet selection modal
3. User chooses their wallet
4. Wallet extension prompts for permission
5. Public key is retrieved and stored
6. Balances are fetched automatically

## Using Wallet Integration

### With WalletProvider (Recommended)

```tsx
// app/layout.tsx
import { WalletProvider } from '@/contexts';

export default function RootLayout({ children }) {
  return <WalletProvider>{children}</WalletProvider>;
}

// Any component
import { useWallet } from '@/contexts';

function MyComponent() {
  const { connected, publicKey, connect, disconnect, walletName } = useWallet();

  return (
    <button onClick={connected ? disconnect : connect}>
      {connected ? `Disconnect ${walletName}` : 'Connect Wallet'}
    </button>
  );
}
```

### With useStellarWallet (Standalone)

```tsx
import { useStellarWallet } from '@/hooks/useStellarWallet';

function MyComponent() {
  const { connected, publicKey, connect, disconnect } = useStellarWallet();

  // Same core fields as useWallet, without the multi-account
  // (accounts, switchAccount) and network mismatch fields
}
```

### Pre-built Button Component

```tsx
import WalletConnectButton from '@/components/WalletConnectButton';

function Header() {
  return <WalletConnectButton theme="dark" />;
}
```

## Session Persistence

Wallet sessions persist across page reloads via localStorage:

```typescript
// Stored on connection
localStorage.setItem('stellar_wallet_connected', 'true');
localStorage.setItem('stellar_wallet_id', 'freighter');
localStorage.setItem('stellar_wallet_address', 'GABC...');
localStorage.setItem('stellar_wallet_name', 'Freighter');

// Cleared on disconnect
localStorage.removeItem('stellar_wallet_connected');
// ... etc
```

On page load, the provider checks for an existing session and auto-reconnects.

## Transaction Signing

When transactions need to be signed, the wallet kit handles it:

```tsx
import { signTransaction } from '@/lib/stellar-wallet-kit';

// Sign an XDR transaction; the network is set when the kit is created
const signedTxXdr = await signTransaction({
  unsignedTransaction: unsignedXdr,
  address: publicKey,
});
```

Most hooks handle signing internally:

```tsx
const { sendPayment } = useWallet();

// sendPayment automatically builds, prompts wallet for signing, and submits
await sendPayment({
  to: 'GDEF...',
  amount: '10',
  asset: 'XLM',
});
```

## Adding More Wallets

Wallets are enabled through the `--wallets` flag when you scaffold:

```bash
npx nextellar my-app --wallets freighter,albedo,lobstr,xbull
```

In an existing project, add the wallet id (`freighter`, `albedo`, `lobstr`,
`xbull`, `hana`, `ledger` or `walletconnect`) to the `INJECTED_WALLETS` array in
`src/lib/stellar-wallet-kit.ts`.

## Network Configuration

### Testnet (Default)

```typescript
const kit = new StellarWalletsKit({
  network: WalletNetwork.TESTNET,
  // ...
});
```

### Mainnet

```typescript
const kit = new StellarWalletsKit({
  network: WalletNetwork.PUBLIC,
  // ...
});
```

### Dynamic Switching

```typescript
// Store preference
localStorage.setItem('network', 'mainnet');

// Read and configure
const network =
  localStorage.getItem('network') === 'mainnet'
    ? WalletNetwork.PUBLIC
    : WalletNetwork.TESTNET;
```

## Error Handling

### Wallet Not Installed

```tsx
const handleConnect = async () => {
  try {
    await connect();
  } catch (error) {
    if (error.message.includes('not installed')) {
      alert('Please install a Stellar wallet extension');
    }
  }
};
```

### User Rejected

```tsx
try {
  await connect();
} catch (error) {
  if (
    error.message.includes('rejected') ||
    error.message.includes('cancelled')
  ) {
    console.log('User cancelled connection');
  }
}
```

### Transaction Rejection

```tsx
try {
  await sendPayment({ to, amount });
} catch (error) {
  if (error.message.includes('User rejected')) {
    alert('Transaction was cancelled');
  }
}
```

## Wallet State

The `useWallet` hook provides:

```typescript
interface WalletState {
  connected: boolean; // Is wallet connected?
  publicKey?: string; // Stellar G-address
  walletName?: string; // "Freighter", "Albedo", etc.
  balances: Balance[]; // Account balances
  accounts: WalletAccount[]; // Accounts exposed by the wallet
  currentAccountIndex: number;
  connect: () => Promise<void>;
  disconnect: () => void;
  refreshBalances: () => Promise<void>;
  switchAccount: (address: string) => Promise<void>;
  sendPayment?: (
    opts: PaymentOptions
  ) => Promise<SubmitTransactionResponse | UnsignedFeeBumpResult>;
  walletNetworkPassphrase?: string; // Network reported by the wallet
  networkMismatch: boolean; // Wallet network differs from the app's
}
```

## Freighter-Specific Notes

Freighter is the most popular Stellar wallet. Some specific notes:

- **Network**: Ensure Freighter is set to the same network (testnet/mainnet) as your app
- **Permissions**: Users may need to allow your site in Freighter settings
- **Multiple Accounts**: Freighter supports multiple accounts - the active one is used
