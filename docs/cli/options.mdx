# CLI Options

Detailed reference for all command-line options available in Nextellar CLI.

The following index mirrors the current CLI registrations. Options are grouped by the command that accepts them; `doctor`, `add`, `upgrade`, and `deploy` options are not scaffold flags.

| Command                        | Options                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nextellar <project-name>`     | `--typescript` (`-t`), `--javascript` (`-j`), `--template <name>`, `--horizon-url <url>`, `--soroban-url <url>`, `--wallets <list>` (`-w`), `--defaults` (`-d`), `--yes` (`-y`), `--skip-install`, `--package-manager <manager>`, `--with-contracts` (`-c`), `--force`, `--no-git`, `--git-init`, `--install-timeout <ms>`, `--no-telemetry` |
| `nextellar doctor`             | `--json`, `--fix`, `--horizon-url <url>`, `--soroban-url <url>`                                                                                                                                                                                                                                                                              |
| `nextellar add [feature]`      | `--list` (`-l`), `--force` (`-f`), `--skip-install`, `--package-manager <manager>`                                                                                                                                                                                                                                                           |
| `nextellar upgrade`            | `--dry-run`, `--check`, `--yes`                                                                                                                                                                                                                                                                                                              |
| `nextellar deploy`             | `--dry-run`, `--size-threshold <bytes>`                                                                                                                                                                                                                                                                                                      |
| `nextellar clean`              | No command-specific options                                                                                                                                                                                                                                                                                                                  |
| `nextellar telemetry <action>` | Positional action: `status`, `enable`, or `disable`; no flags                                                                                                                                                                                                                                                                                |

The global `--help` (`-h`) and `--version` (`-v`) options are also available.

## Language Options

### --typescript, -t

Generate a TypeScript project (default).

````bash
nextellar my-app --typescript
## or
nextellar my-app -t
```css

**Default:** `true`
**Type:** Boolean
**Status:** Supported

## --javascript, -j

Generate a JavaScript project.

```bash
nextellar my-app --javascript
## or
nextellar my-app -j
```css

**Default:** `false`
**Type:** Boolean
**Status:** Supported with `default`, `minimal`, and `defi` templates

## Network Configuration

### --horizon-url

Override the default Horizon endpoint.

```bash
nextellar my-app --horizon-url https://horizon.stellar.org
```css

**Default:** Flag unset; scaffold fallback is `https://horizon-testnet.stellar.org`
**Type:** String (URL)
**Validation:** Must be a valid HTTP/HTTPS URL when provided.

**Common Values:**

- Testnet: `https://horizon-testnet.stellar.org`
- Mainnet: `https://horizon.stellar.org`
- Custom: Your own Horizon instance

### --soroban-url

Override the default Soroban RPC endpoint.

```bash
nextellar my-app --soroban-url https://soroban-rpc.stellar.org
```css

**Default:** Flag unset; scaffold fallback is `https://soroban-testnet.stellar.org`
**Type:** String (URL)
**Validation:** Must be a valid HTTP/HTTPS URL when provided.

**Common Values:**

- Testnet: `https://soroban-testnet.stellar.org`
- Mainnet: `https://soroban-rpc.stellar.org`

## Wallet Configuration

### --wallets, -w

Specify which wallet adapters to include.

```bash
nextellar my-app --wallets freighter,xbull
## or
nextellar my-app -w freighter,albedo
```

**Default:** `freighter,albedo,lobstr`
**Type:** Comma-separated string

For a complete list of supported wallets, examples, and detailed information about defaults and unknown adapter behavior, see [Wallet Configuration](/docs/cli/flags#wallet-configuration-wallets) in the Flags & Options reference.

**Quick Reference:**

**Supported Wallets:** `freighter`, `albedo`, `lobstr`, `xbull`, `hana`

**Examples:**

```bash
## Only Freighter
nextellar my-app --wallets freighter

## Custom combination (non-default)
nextellar my-app --wallets freighter,xbull

## All supported wallets
nextellar my-app --wallets freighter,albedo,lobstr,xbull,hana
```

## Installation Options

### --skip-install

Skip automatic dependency installation.

```bash
nextellar my-app --skip-install
````

**Default:** `false`
**Type:** Boolean

**Use Cases:**

- Install dependencies manually later.
- Use a different package manager.

**After Skipping:**

````bash
cd my-app
npm install  # or yarn install, pnpm install
```css

### --package-manager

Choose which package manager to use.

```bash
nextellar my-app --package-manager pnpm
```css

**Default:** Auto-detected
**Type:** String
**Options:** `npm`, `yarn`, `pnpm`, `bun`

**Detection Priority:**

1. Explicit `--package-manager` flag
2. `npm_config_user_agent` environment variable
3. Lockfile presence (`bun.lockb`, `bun.lock`, `pnpm-lock.yaml`, `yarn.lock`, `package-lock.json`)
4. Fallback to `npm`

### --install-timeout

Set installation timeout in milliseconds.

```bash
nextellar my-app --install-timeout 3600000
```css

**Default:** `1200000` (20 minutes)
**Type:** Number (milliseconds)
**Range:** `5000` - `3600000` milliseconds (5 seconds - 1 hour)

**Use Cases:**

- Slow network connections
- Large dependency trees
- CI/CD environments with timeouts

**Common Values:**

- 5 minutes: `300000`
- 10 minutes: `600000`
- 20 minutes: `1200000` (default)
- 30 minutes: `1800000`
- 1 hour: `3600000`

## Scaffold Options

These options control Git initialization during scaffolding.

### --git-init

This flag is registered by the CLI, but Git initialization is already enabled by default. Pass `--no-git` to disable it.

```bash
npx nextellar my-app --git-init
```

**Default:** `false` (the flag is unset)
**Type:** Boolean
**Status:** Supported

The current scaffold action does not need this flag to initialize Git; it is redundant with the default behavior.

---

### --no-git

Skip git initialization when scaffolding.

```bash
npx nextellar my-app --no-git
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported

**Use Cases:**

- You intend to move the project into an existing git repository.
- Your CI scaffold step does not need a git history.
- You want to initialize git yourself with custom config.

```bash
npx nextellar my-app --no-git
cd my-app
git init --initial-branch=main
git remote add origin git@github.com:you/my-app.git
```

## Other Scaffold Options

### --template <name>

Choose one of the three template families. The default is `default`; `--javascript` selects the JavaScript variant of the chosen family.

```bash
npx nextellar my-app --template minimal
npx nextellar my-js-app --template defi --javascript
```

**Accepted values:** `default`, `minimal`, `defi`

### --with-contracts, -c

Add the Soroban contract overlay to the scaffold. The CLI also enables the overlay automatically for `--template defi`.

```bash
npx nextellar my-app --template minimal --with-contracts
```

**Default:** `false` for non-DeFi templates; enabled for `defi`

### --force

Overwrite an existing target directory. In an interactive terminal the CLI asks for confirmation unless `--defaults` is set; in non-interactive use the directory is removed without a prompt.

```bash
npx nextellar my-app --force
```

**Default:** `false`

### --no-telemetry

Disable telemetry for this scaffold invocation. Without the flag, telemetry behavior follows the saved preference; `NEXTELLAR_TELEMETRY_DISABLED` can force it off for the environment.

```bash
npx nextellar my-app --no-telemetry
```

## Behavior Options

### --defaults, -d, --yes, -y

Skip prompts and use default values. `--yes` and `-y` are accepted aliases for `--defaults`.

```bash
nextellar my-app --defaults
## or
nextellar my-app -d
## or
nextellar my-app --yes
## or
nextellar my-app -y
```

**Default:** `false`
**Type:** Boolean
**Aliases:** `-d`, `--yes`, `-y`

**Use Cases:**

- CI/CD pipelines
- Automated scripts
- Quick testing
- Non-interactive environments

> **Note:** In an interactive terminal, Nextellar can prompt for scaffold configuration. Use `--defaults` (or `--yes` / `-y`) to skip prompts and apply default values instead.

## Feature Add Options

The following options apply to the `nextellar add` command:

### --list, -l

List all available features that can be added to the project.

```bash
nextellar add --list
## or
nextellar add -l
````

**Type:** Boolean
**Status:** Supported

---

## --force, -f

Force addition of a feature, overwriting existing files without prompting.

```bash
nextellar add freighter --force
## or
nextellar add freighter -f
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported

---

## --skip-install

Add the feature's files without running the package manager install step.

```bash
nextellar add freighter --skip-install
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported

Useful when you want to batch several `nextellar add` calls and install once at the end:

```bash
nextellar add freighter --skip-install
nextellar add xbull --skip-install
npm install
```

---

### --package-manager (add)

Choose which package manager to use for the post-add install step.

```bash
nextellar add freighter --package-manager pnpm
```

**Default:** Auto-detected
**Type:** String
**Options:** `npm`, `yarn`, `pnpm`
**Status:** Supported

Combine with `--force` to overwrite files and install with a specific package manager:

```bash
nextellar add freighter --force --package-manager pnpm
```

## Doctor Options

The following options apply to the `nextellar doctor` command:

### --json

Print diagnostic results as JSON for CI and other automation.

```bash
nextellar doctor --json
```

**Default:** `false`
**Type:** Boolean

### --fix

Offer to automatically fix safe or optional diagnostic failures.

```bash
nextellar doctor --fix
```

**Default:** `false`
**Type:** Boolean

### --horizon-url (doctor)

Override the Horizon endpoint that `doctor` uses for its connectivity check.

```bash
nextellar doctor --horizon-url https://horizon.stellar.org
```

**Default:** Project config value, falling back to `https://horizon-testnet.stellar.org`
**Type:** String (URL)
**Status:** Supported

---

### --soroban-url (doctor)

Override the Soroban RPC endpoint that `doctor` uses for its connectivity check.

```bash
nextellar doctor --soroban-url https://soroban-rpc.stellar.org
```

**Default:** Project config value, falling back to `https://soroban-testnet.stellar.org`
**Type:** String (URL)
**Status:** Supported

Check mainnet connectivity in one command:

```bash
nextellar doctor \
  --horizon-url https://horizon.stellar.org \
  --soroban-url https://soroban-rpc.stellar.org
```

## Upgrade Options

The following options apply to the `nextellar upgrade` command:

### --dry-run

Show which template files would change without applying the upgrade.

```bash
nextellar upgrade --dry-run
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported

---

### --check

Show a changelog-style preview of available upgrades and exit with a non-zero code if any updates are available. Includes human-readable upgrade notes (breaking changes, migration hints) in addition to the file diff shown by `--dry-run`.

```bash
nextellar upgrade --check
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported
**Exit code:** `0` = up to date; `1` = updates available

**Difference from `--dry-run`:**

|                                  | `--dry-run` | `--check` |
| -------------------------------- | ----------- | --------- |
| Shows file diff                  | ✅          | ✅        |
| Shows changelog/upgrade notes    | ❌          | ✅        |
| Non-zero exit when updates exist | ❌          | ✅        |
| Suitable for CI gate             | No          | **Yes**   |

Use `--check` in CI to fail a pipeline when the project is behind the latest template:

```bash
nextellar upgrade --check || echo "Project needs upgrade"
```

---

### --yes

Apply upgrade changes without prompting for confirmation.

```bash
nextellar upgrade --yes
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported

---

## Deployment Options

The following options apply to the `nextellar deploy` command:

### --dry-run

Validate the project configuration and production build without generating a final deployment bundle.

```bash
nextellar deploy --dry-run
```

**Default:** `false`
**Type:** Boolean
**Status:** Supported

---

### --size-threshold

Fail the deploy command if the production bundle exceeds the specified size in bytes.

```bash
nextellar deploy --size-threshold 20971520
```

**Default:** `52428800` (50 MB)
**Type:** Number (bytes)
**Status:** Supported

**Common threshold values:**

- 10 MB: `10485760`
- 20 MB: `20971520`
- 50 MB: `52428800` (default)
- 100 MB: `104857600`

```bash
## Use the default 50 MB threshold
nextellar deploy

## Enforce a stricter 20 MB limit
nextellar deploy --size-threshold 20971520

## Combine with dry-run to check bundle size without deploying
nextellar deploy --dry-run --size-threshold 20971520
```

## Environment Variables

Nextellar respects these environment variables:

### npm_config_user_agent

Used for package manager detection.

```bash
## Set by package managers automatically
npm_config_user_agent="npm/10.2.0 node/v20.10.0"
```

## Validation Rules

### Project Name

The scaffold requires a project name and validates it with `validate-npm-package-name`. The CLI does not use a custom regular expression; the validator may also suggest a slug when it can derive one.

### URLs

`--horizon-url` and `--soroban-url` must parse as valid `http://` or `https://` URLs when supplied. The CLI does not check endpoint reachability while scaffolding.

### Wallet Names

`--wallets` is split on commas and surrounding whitespace is trimmed. The scaffold CLI does not validate adapter names or normalize their case; use supported lowercase IDs such as `freighter`, `albedo`, `lobstr`, `xbull`, and `hana`.
