# Nextellar Upgrade Workflow

Use `nextellar upgrade` when an existing project should receive the latest template improvements without recreating the app. The safest path is to check first, preview the planned changes, and only then apply the upgrade.

## Safe Workflow

```bash
nextellar upgrade --check
nextellar upgrade --dry-run
nextellar upgrade
```

Run the command from the project root. If the project has local changes, commit or stash them before applying the upgrade so generated files can be reviewed clearly.

## Flags

| Flag                     | Purpose                                                                    |
| ------------------------ | -------------------------------------------------------------------------- |
| `--check`                | Reports whether an upgrade is available without writing files.             |
| `--dry-run`              | Shows the files that would change without applying them.                   |
| `--yes`                  | Skips prompts for automation after the dry-run output is already reviewed. |
| `--package-manager <pm>` | Uses the selected package manager for dependency follow-up steps.          |

## Review Checklist

- Review generated configuration changes before committing them.
- Check Stellar network, wallet, and Soroban settings for local overrides.
- Keep application-specific customizations that should not be replaced by template defaults.
- Use `--check` in CI when you only need to detect whether the project is behind.
