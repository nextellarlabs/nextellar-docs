# Verified Template Feature Matrix

This document provides a definitive, source-verified feature matrix for all Nextellar templates and their variants. Use this to determine which template best matches your project requirements.

---

## Quick Summary

Nextellar ships **3 core templates** + **2 language variants** + **1 contract overlay**:

| Category              | Templates                                         |
| --------------------- | ------------------------------------------------- |
| **Core Templates**    | `default`, `minimal`, `defi`                      |
| **Language Variants** | TypeScript (default), JavaScript (`--javascript`) |
| **Overlays**          | Soroban contracts (`--with-contracts`)            |

This creates 6 primary template configurations (3 templates × 2 languages), plus optional contract support across all.

## Template-by-Template Breakdown

### Template: `default`

**Purpose:** Full-featured Stellar + Soroban development.

**Best For:**

- New developers exploring Stellar
- Comprehensive dApps needing broad feature access
- Apps requiring transaction history
- Soroban smart contract integration

**TypeScript Scaffold:**

```bash
npx nextellar my-app --template default
## or simply:
npx nextellar my-app
```

**Includes:**

- ✓ All wallet hooks (8 total)
- ✓ All components (2 total)
- ✓ Full lib setup (networks, storage, wallet kit)
- ✓ `.env.example` with sample variables
- ✓ TypeScript configuration

**JavaScript Variant:**

```bash
npx nextellar my-app --template default --javascript
```

**Changes from TypeScript:**

- `.tsx` → `.jsx`
- `.ts` → `.js`
- `tsconfig.json` remains

**With Contracts:**

```bash
npx nextellar my-app --template default --with-contracts
```

**Adds:**

- `contracts/` directory with Rust sample
- `contracts/hello_world/` Soroban contract
- `contracts:build` npm script
- `contracts:test` npm script
- `NEXT_PUBLIC_HELLO_WORLD_CONTRACT_ID` in `.env.example`

## Language Variant Specifications

### TypeScript Variant (Default)

**File Extensions:**

- React components: `.tsx`
- Utilities: `.ts`
- Configuration: `.ts`

**Includes:**

- `tsconfig.json` with strict mode enabled
- Type definitions for all hooks and components
- Full IDE autocomplete support

**Package.json Scripts:**

- `npm run dev` — Next.js development server
- `npm run build` — Production build with type checking
- `npm run lint` — ESLint on all `.ts`/`.tsx` files
- `npm run type-check` — TypeScript type validation

---

### JavaScript Variant (`--javascript`)

**File Extensions:**

- React components: `.jsx`
- Utilities: `.js`
- Configuration: `.js`

**Key Differences:**

- No `tsconfig.json` (JavaScript by default in Next.js 14+)
- JSDoc comments for type hints
- Same hooks and components available
- Same npm scripts

**Trade-offs:**

- Less IDE type safety (but JSDoc provides hints)
- Smaller bundle size (no TypeScript compiler overhead)
- Faster builds in some cases
- Better for teams unfamiliar with TypeScript

**When to Use:**

- Team prefers JavaScript
- Migrating from existing JS codebases
- Quick prototyping without type overhead

## Contract Overlay Specification

### `--with-contracts` Flag

**Applies To:** All templates (default, minimal, defi) + both languages (TS, JS)

**Directory Structure Added:**

```
contracts/
├── hello_world/           # Sample Soroban contract
│   ├── Cargo.toml        # Rust package config
│   ├── src/
│   │   ├── lib.rs        # Contract code
│   │   └── test.rs       # Contract tests
│   └── target/           # Build output (generated)
└── Makefile              # Build helpers
```

**npm Scripts Added:**

```json
{
  "scripts": {
    "contracts:build": "cd contracts && cargo build --target wasm32-unknown-unknown --release",
    "contracts:test": "cd contracts && cargo test",
    "contracts:deploy": "soroban contract deploy --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.wasm"
  }
}
```

**Environment Variables Added:**

```bash
## .env.example
NEXT_PUBLIC_HELLO_WORLD_CONTRACT_ID=CAB3...
```

**Verification:**

- Sample contract compiles with `npm run contracts:build`
- Tests pass with `npm run contracts:test`
- Contract ID placeholder provided in `.env.example`

## Feature Combinations Reference

### Scenario: "I want a full-featured app with contracts"

**Recommendation:** `default` + `--with-contracts`

```bash
npx nextellar my-app --template default --with-contracts
```

**You Get:**

- ✓ All 8 wallet hooks
- ✓ Soroban smart contract support
- ✓ Transaction history
- ✓ Network switching
- ✓ Contract scaffolding + build scripts

---

### Scenario: "I want a simple JavaScript wallet connector"

**Recommendation:** `minimal` + `--javascript`

```bash
npx nextellar my-app --template minimal --javascript
```

**You Get:**

- ✓ Wallet connection (JavaScript)
- ✓ Balance checking
- ✓ Minimal dependencies
- ✓ No TypeScript setup needed

---

### Scenario: "I'm building a DEX and want TypeScript"

**Recommendation:** `defi` (TypeScript is default)

```bash
npx nextellar my-app --template defi
```

**You Get:**

- ✓ Payment sending
- ✓ Asset trustlines
- ✓ DEX order book
- ✓ Full TypeScript setup
- ✓ Type-safe hooks

## Adding Features Post-Scaffold

The `nextellar add` command allows adding features to any template after creation:

```bash
## Start with minimal
npx nextellar my-app --template minimal

## Add features incrementally
nextellar add soroban-contract        # Adds Soroban support
nextellar add transaction-history     # Adds history hook
nextellar add offer-book              # Adds DEX order book
nextellar add network-switcher        # Adds network UI
```

This allows fine-grained control over your starter scaffold.
