# `nextellar doctor --json` — CI Integration Guide

> Related: [Document `doctor --json` for CI pipelines #649](https://github.com/nextellarlabs/nextellar-docs/issues/649)
> Coordinate with the CLI's `doctor-json` schema-freeze issue. This page documents `schemaVersion: "1.0.0"`.

Run environment diagnostics to verify a machine (or CI runner) is ready for Nextellar development. The `doctor` command checks local tooling, network connectivity to Stellar endpoints, and available system resources.

```bash
nextellar doctor [options]
```

## Options

| Option   | Description                              |
| -------- | ----------------------------------------- |
| `--json` | Output results as JSON for CI integration |

## What It Checks

| Check          | Required | Description                                          |
| --------------- | -------- | ----------------------------------------------------- |
| Node.js         | Yes      | Version 20 or later                                   |
| npm             | Yes      | Package manager bundled with Node.js                  |
| yarn            | No       | Optional package manager                              |
| pnpm            | No       | Optional package manager                              |
| Git             | Yes      | Version control for project scaffolding               |
| Rust            | No       | Needed for Soroban contract development                |
| Stellar CLI     | No       | Needed for contract deployment and testing             |
| wasm32 target   | No       | Rust target for compiling Soroban contracts             |
| Horizon API     | Yes      | Reachability of the default testnet Horizon endpoint    |
| Soroban RPC     | No       | Reachability of the default testnet Soroban RPC endpoint |
| Free memory     | Yes      | At least 1 GB of available RAM                          |

## JSON Output for CI Pipelines

When run with `--json`, the command outputs a structured JSON object designed for CI/CD integration.

```bash
nextellar doctor --json
```

### Complete JSON Structure

```json
{
  "schemaVersion": "1.0.0",
  "checks": [
    {
      "id": "node",
      "name": "Node.js",
      "required": true,
      "ok": true,
      "detail": "v20.18.0 (>= 20.0.0 required)",
      "fix": "Install Node.js v20.x or higher from https://nodejs.org",
      "link": "https://nextellar.com/docs/requirements"
    },
    {
      "id": "horizon-api",
      "name": "Horizon API",
      "required": true,
      "ok": false,
      "detail": "Connection timeout to https://horizon-testnet.stellar.org",
      "fix": "Check your network connection and firewall settings",
      "link": "https://nextellar.com/docs/troubleshooting/horizon-issues"
    }
  ],
  "summary": {
    "total": 10,
    "passed": 9,
    "failed": 1,
    "requiredFailed": 1
  }
}
```

### Field Descriptions

| Field                    | Type    | Description                                                    |
| ------------------------- | ------- | ---------------------------------------------------------------- |
| `schemaVersion`           | string  | Version of the output schema for forward compatibility           |
| `checks`                  | array   | List of all system checks performed                               |
| `checks[].id`             | string  | Unique identifier for the check (e.g., `"node"`, `"horizon-api"`) |
| `checks[].name`           | string  | Human-readable name of the check                                  |
| `checks[].required`       | boolean | Whether this check must pass for the system to be considered healthy |
| `checks[].ok`             | boolean | Whether the check passed (`true`) or failed (`false`)             |
| `checks[].detail`         | string  | Detailed message about the check result                            |
| `checks[].fix`            | string  | Instructions on how to fix the issue if the check failed           |
| `checks[].link`           | string  | URL to relevant documentation for more information                 |
| `summary`                 | object  | Aggregated results of all checks                                   |
| `summary.total`           | number  | Total number of checks performed                                   |
| `summary.passed`          | number  | Number of checks that passed                                       |
| `summary.failed`          | number  | Number of checks that failed (both required and optional)          |
| `summary.requiredFailed`  | number  | Number of required checks that failed                              |

### Exit Codes

| Exit Code | Meaning                          |
| --------- | ---------------------------------- |
| `0`       | All required checks passed         |
| `1`       | One or more required checks failed |

> Optional check failures do **not** affect the exit code — they're reported in the JSON output but don't cause the command to fail.

## CI/CD Integration Examples

### GitHub Actions

```yaml
name: Check Nextellar Environment

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  doctor-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install Nextellar CLI
        run: npm install -g nextellar

      - name: Run Nextellar Doctor
        id: doctor
        run: |
          # Run doctor and capture JSON output
          npx nextellar doctor --json > doctor-output.json

          # Display the output for debugging
          cat doctor-output.json

          # Check if any required checks failed
          if jq -e '.summary.requiredFailed > 0' doctor-output.json > /dev/null; then
            echo "❌ Required checks failed!"
            echo "Failed required checks:"
            jq '.checks[] | select(.required == true and .ok == false) | {id, name, detail, fix}' doctor-output.json
            exit 1
          else
            echo "✅ All required checks passed!"
            exit 0
          fi

      - name: Upload doctor report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: doctor-report
          path: doctor-output.json
```

### GitLab CI

```yaml
doctor:
  stage: test
  image: node:20
  script:
    - npm install -g nextellar
    - npx nextellar doctor --json > doctor-output.json
    - |
      if jq -e '.summary.requiredFailed > 0' doctor-output.json > /dev/null; then
        echo "❌ Required checks failed!"
        jq '.checks[] | select(.required == true and .ok == false) | {id, name, detail, fix}' doctor-output.json
        exit 1
      else
        echo "✅ All required checks passed!"
        exit 0
      fi
  artifacts:
    paths:
      - doctor-output.json
    expire_in: 7 days
```

### CircleCI

```yaml
version: 2.1

jobs:
  doctor-check:
    docker:
      - image: cimg/node:20.0
    steps:
      - checkout
      - run:
          name: Install Nextellar CLI
          command: npm install -g nextellar
      - run:
          name: Run Nextellar Doctor
          command: |
            npx nextellar doctor --json > doctor-output.json
            if jq -e '.summary.requiredFailed > 0' doctor-output.json > /dev/null; then
              echo "❌ Required checks failed!"
              jq '.checks[] | select(.required == true and .ok == false) | {id, name, detail, fix}' doctor-output.json
              exit 1
            else
              echo "✅ All required checks passed!"
              exit 0
            fi
      - store_artifacts:
          path: doctor-output.json
```

## Using `jq` for Advanced Parsing

```bash
# Get a list of all failed checks (both required and optional)
jq '.checks[] | select(.ok == false) | .name' doctor-output.json

# Check if a specific check passed
jq '.checks[] | select(.id == "horizon-api") | .ok' doctor-output.json

# Generate a summary report
jq '{status: if .summary.requiredFailed == 0 then "PASS" else "FAIL" end, total: .summary.total, failed: .summary.failed}' doctor-output.json

# Count total failures
jq '.summary.failed' doctor-output.json
```
